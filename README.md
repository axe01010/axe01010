# Harry

> Understanding systems. Building useful software. Publishing the process.

Most repositories here begin with a problem, not a roadmap.

I spend most of my time inspecting runtime behavior, reading source code, and reducing complex systems into something practical. Once the problem is understood, I build tools that make the same problem easier to solve next time.

Current work spans Android systems, developer tooling, AI agents, reverse engineering, and open source infrastructure. Some repositories become polished projects. Others remain research because the investigation is still producing useful answers.

## Current Work

### Android Systems

Runtime analysis, instrumentation, debugging workflows, and platform internals.

### AI Engineering

Developer agents, local-first workflows, MCP integrations, and practical automation.

### Developer Tooling

Tools that reduce friction without adding unnecessary abstraction.

### Research

Experiments, implementation notes, architecture sketches, and failed ideas that are worth documenting.

---

## Working Principles

- Observe before changing.
- Prefer evidence over assumptions.
- Build the smallest useful solution.
- Document decisions and trade-offs.
- Keep experiments public whenever possible.
